\section{Audio CD Subcode}

\subsection{Subcode Datarate}
The datarate of the subcode in subcode block/s is 75 Hz. A subcoding block should consists of 98 subcoding symbols which each have a size of 8 bits, but the first 2 subcoding symbols are replaced by the subcoding sync patterns S0 and S1. This means the subcode has a datarate of 57600 bits/s (75 * 96 * 8). (BS\_Standard 17.3)

\subsection{Track Information}
This information is stored in the Q-channel which is one of the subcoding channels. As mentioned in question 1 a subcoding block consists of 98 subcoding symbols. This means a subcoding block contains 98 Q-bits. The first 2 Q-bits are part of the subcoding sync patterns, the next 4 are control bits and the 4 bits after that are the address bits that determine the mode which tells what information the following 72 bits will hold. Only if the address bits determine that the mode is mode 1, these 72 bits will contain info about the number of tracks, the starting positions of the tracks and the total playing time of the audio CD. The first 8 bits of the 72-bit datafield will tell you which track the subcoding block is part of. If these bits are 00 it means the block is part of the lead-in track which means it will contain additional information about the real tracks. Blocks that are part of the lead-in track will have the fields POINT, PMIN, PSEC and PFRAME. If the value of POINT is A0 in a block PMIN will give the track number of the first track on the disc, if POINT has value A1 PMIN will give the track number of the last track on the disc. This way the total number of tracks can be deducted. If the value of POINT is between 01 and 99 the fields PMIN, PSEC and PFRAME will contain the absolute time at which the track with the same track number as the value in POINT will start. If POINT has value A2 PMIN, PSEC and PRFAME point to the absolute time the lead-out track starts. Since you now know when the first track starts and the lead-out track starts, you also know the total playing time of the audio.

To protect the data from errors 2 different techniques are used. First of all, during the duration of the lead-in track this info about the timing of the tracks is continuously looped and is also always repeated 3 times in subsequent subcoding blocks. Secondly the last 16 Q-bits of every subcoding block are part of a Cyclic Redundancy Check code, which is a checksum which helps to detect errors. (BS\_Standard 17.5)

\section{Reed-Solomon Code}

\subsection{Encoding}

\subsubsection{Primitive polynomial}
% Q1a: Show that p(D) = D^8 + D^4 + D^3 + D^2 + 1 is a primitive polynomial with root alpha for GF(2^8).

We need two things: $p(D) = D^8 + D^4 + D^3 + D^2 + 1$ must be irreducible over $\text{GF}(2)$, and its root $\alpha$ must have multiplicative order $2^8 - 1 = 255$.

\paragraph{Irreducibility.}
$p(D)$ has no roots in $\text{GF}(2)$: $p(0) = 1 \neq 0$ and $p(1) = 1+1+1+1+1 = 1 \neq 0$ (mod 2).
Since $\deg p = 8$, any factorisation would include a factor of degree $\leq 4$. Checking division by all irreducible polynomials of degree 2, 3, and 4 over $\text{GF}(2)$ yields a nonzero remainder in every case, so $p(D)$ is irreducible.

\paragraph{Primitivity.}
Let $\alpha$ be a root of $p(D)$, giving us the reduction rule $\alpha^8 = \alpha^4 + \alpha^3 + \alpha^2 + 1$.
Since $255 = 3 \times 5 \times 17$, it suffices to check that $\alpha^d \neq 1$ for $d \in \{85, 51, 15\}$. Computing powers via repeated multiplication and reduction:
\begin{align*}
\alpha^{15} &= \alpha^5 + \alpha^2 + \alpha = 38 \neq 1,\\
\alpha^{51} &= 10 \neq 1,\\
\alpha^{85} &= 214 \neq 1.
\end{align*}
Meanwhile $\alpha^{255} = 1$ because $|\text{GF}(2^8)^*| = 255$. So the order of $\alpha$ is exactly 255, and $p(D)$ is primitive.

\subsubsection{Generator polynomial}
% Q1b: Construct g(x) for the C1 RS code. Give coefficients g_i in GF(2^8). What is m_0?

The $C_1$ code is RS(32,28) over $\text{GF}(2^8)$ with $t = 2$ (IEC~60908, Section~16.3). From the parity check matrix $H_p$ in Figure~11 of the standard and the course notes (slide~145), $m_0 = 1$, so the generator polynomial has roots $\alpha, \alpha^2, \alpha^3, \alpha^4$:
\[
g(x) = (x + \alpha)(x + \alpha^2)(x + \alpha^3)(x + \alpha^4)
\]
(using $-1 = 1$ in characteristic 2). Expanding in pairs:
\begin{align*}
(x+\alpha)(x+\alpha^2) &= x^2 + (\alpha+\alpha^2)x + \alpha^3, \\
(x+\alpha^3)(x+\alpha^4) &= x^2 + (\alpha^3+\alpha^4)x + \alpha^7,
\end{align*}
and multiplying these two quadratics:
\begin{align*}
g(x) &= x^4 + (\alpha+\alpha^2+\alpha^3+\alpha^4)\,x^3
+ (\alpha^3+\alpha^4+\alpha^6+\alpha^7)\,x^2 \\
&\quad + (1+\alpha+\alpha^2+\alpha^5+\alpha^6+\alpha^7)\,x
+ (\alpha^2+\alpha^4+\alpha^5+\alpha^6).
\end{align*}

Writing $g(x) = g_0 + g_1 x + g_2 x^2 + g_3 x^3 + g_4 x^4$, the coefficients are:

\subsubsection{Check polynomial}
% Q1c: Give the check polynomial h(x). First and last 5 terms sufficient.

For the full RS(255,251) code, $x^{255} + 1 = g(x) \cdot h(x)$ (since $-1 = 1$ in characteristic~2).
The check polynomial $h(x)$ has degree 251; its roots are all $\alpha^i$ with $i \notin \{1,2,3,4\}$, i.e.\ $\alpha^0, \alpha^5, \alpha^6, \ldots, \alpha^{254}$.

Computing the division gives the first and last five terms:
\[
h(x) = x^{251} + \alpha^{76}x^{250} + \alpha^{165}x^{249} + \alpha^{134}x^{248} + \alpha^{147}x^{247} + \cdots + \alpha^{109}x^3 + \alpha^{145}x^2 + \alpha^{61}x + \alpha^{245}
\]

\subsubsection{Minimum Hamming distance}
% Q1d: What is the minimal Hamming distance? Use the MDS property.

RS codes are MDS codes (maximum distance separable), meaning they meet the Singleton bound with equality:
\[
d_{\min} = n - k + 1 = 32 - 28 + 1 = 5
\]
This allows correction of $t = \lfloor(d_{\min}-1)/2\rfloor = 2$ symbol errors, or detection of up to 4.

\subsubsection{Reed-Solomon vs.\ binary BCH}
% Q1e: Why is RS more appropriate for data protection than binary BCH?

RS codes over $\text{GF}(2^8)$ work on 8-bit symbols rather than individual bits. This is a better fit for CD audio for two reasons.

First, burst errors within a single byte count as only one symbol error for RS. A binary BCH code would treat the same burst as up to 8 separate bit errors, requiring much higher correction capability. A burst corrupting all 8 bits of one byte costs the RS decoder just one of its $t=2$ corrections, while a binary BCH code would need $t \geq 8$.

Second, audio data is stored as bytes, so RS codes in $\text{GF}(2^8)$ match the data format directly. The code rate is also better: RS needs only $2t$ parity symbols (here 4 bytes) to correct $t$ symbol errors, whereas a binary BCH code protecting against the same burst lengths would require many more parity bits.

\subsubsection{Implementation of \texttt{makeGenerator()} and \texttt{encode()}}
% Q1f: Describe your implementation.

\texttt{makeGenerator(m, t, m0)} builds the generator polynomial by starting from $g(x) = 1$ and iteratively multiplying by each factor $(x - \alpha^i)$ for $i = m_0, \ldots, m_0+2t-1$, using \texttt{galois.Poly} arithmetic.

\texttt{encode(msg)} performs systematic encoding row by row. For each information word $m(x)$ of length $l$:
\begin{enumerate}
    \item Place $m(x)$ in the high-order positions of a length-$(l + n - k)$ buffer (equivalent to multiplying by $x^{n-k}$).
    \item Compute the remainder $r(x) = m(x) \cdot x^{n-k} \bmod g(x)$.
    \item Output the codeword $[m(x) \mid r(x)]$: the message followed by the parity symbols.
\end{enumerate}

\subsection{Decoding}

\subsubsection{Bit error correction capability}
% Q2a: How many erroneous bits can C1 always correct? Maximum correctable?

$C_1$ corrects up to $t = 2$ symbol errors, with each symbol being 8 bits.

In the worst case, each erroneous bit lands in a different symbol, so $C_1$ can always correct up to 2 erroneous bits. Three bit errors could fall in three different symbols, which exceeds $t=2$.

In the best case, all bit errors are concentrated in at most 2 symbols. Then up to $2 \times 8 = 16$ erroneous bits can be corrected, since the RS decoder only sees 2 corrupted symbols.

\subsubsection{Bit error rate vs.\ symbol error rate}
% Q2b: Relationship between P_b and P_s for GF(2^8).

With independent bit errors at probability $P_b$, a symbol of $m = 8$ bits is erroneous whenever at least one bit is wrong:
\[
P_s = 1 - (1 - P_b)^8
\]
For small $P_b$ this simplifies to $P_s \approx 8\, P_b$.

\subsubsection{Implementation of \texttt{decode()}}
% Q2c: Describe your decoding algorithm.

The decoder implements the PGZ (Peterson-Gorenstein-Zierler) algorithm with Forney's formula. For each received word $r(x)$:

\begin{enumerate}
    \item Compute syndromes $S_j = r(\alpha^{m_0+j})$ for $j = 0, \ldots, 2t-1$. If all are zero, the word is error-free.

    \item Find the error locator polynomial $\Lambda(x)$ via PGZ: try $\nu = t, t-1, \ldots, 1$ errors, building a $\nu \times \nu$ syndrome matrix each time. The first $\nu$ for which the system is solvable gives $\Lambda(x)$.

    \item Chien search: evaluate $\Lambda(\alpha^{-i})$ for each position $i$ in the codeword to find the error locations. If the number of roots does not equal $\nu$, decoding fails.

    \item Forney's algorithm: compute the error evaluator polynomial $\Omega(x) = S(x) \cdot \Lambda(x) \bmod x^{2t}$ and obtain the error values as
    \[
    e_j = \alpha^{i_j(1-m_0)} \cdot \frac{\Omega(\alpha^{-i_j})}{\Lambda'(\alpha^{-i_j})}
    \]
    where $\Lambda'(x)$ is the formal derivative of $\Lambda(x)$.

    \item Correct the received word and verify by recomputing the syndromes. If they are not all zero, the word is flagged as uncorrectable ($\texttt{nERR} = -1$).
\end{enumerate}

\section{Audio Encoding in CDs}

\subsection{CIRC Structure}
% Q1: Explain the function of every component of the CIRC structure (figures 12 and 13 of the standard). Which error types does C1 protect against? And C2?
In the encoder the delay of 2 frames means that if a block with even and odd samples arrives as input a delay of 2 symbols is placed between the even and odd samples. This means that all the even samples in the block are delayed with 2 blocks. Because of this, if 2 subsequent uncorrectable blocks occur, interpolation can still be accomplished to estimate the values. Next an interleaving sequence happens. This means the symbols are scrambled so as to separate even- and odd-numbered data words. If an error now happens concealment can still be performed, which is essentially covering up the error. After this the C2 encoder accepts the 24-byte parallel word and produces 4 bytes of Q parity. Q parity is designed to correct one erroneous symbol or up to four erasures in one word. Now its time for the delay lines of unequal length. Here the 28 bytes are delayed by differing periods, which are integer multiples of 4 blocks. As a result, each C2 word is stored in 28 different blocks, distributed over 109 blocks. Next the C1 encoder accepts a 28-byte word (from 28 different C2 words) and produces 4 more bytes of P parity. The C1 encoder is used to correct single symbol errors and to detect and flag double and triple errors for Q correction. Lastly the delay of 1 frame introduces a fixed delay of one symbol to alternate symbols. This odd/even delay spreads the output words over two data blocks. This prevents random errors from disrupting more than one symbol in one word, even if two adjacent symbols in one block are erroneous.

The operations in the decoder reverse these operations. C1 code is designed to correct random errors and detect burst errors. Short-duration random errors can still be corrected but longer burst errors are detected, flagged and passed along. With the info from the C1 decoder and after de-interleaving the C2 decoder is able to correct the longer burst errors and also the residual random errors. (Ken C. p69-71)

\subsection{Implementation of AudioCD Functions}
% Q2: Describe your implementation of the AudioCD class functions.
The AudioCD class implements the CIRC encoding and decoding pipeline, the architecture is based on the CIRC decoder specifications outlined in the IEC 60908:1999 International Standard \cite[pp.~155, 157]{iec60908_1999}. The \texttt{encode()} method applies the sequence of delays, C2 encoder, delays and C1 encoder. The \texttt{decode()} method reverses the process, including error correction and interpolation for uncorrectable errors.

\subsection{Maximum Correctable Burst}
% Q3: Maximum burst duration (bits) assuming C2 corrects 4 erasures. Translate to scratch width at 1.3 m/s. Compare with simulation results.
The C2 decoder can correct up to 4 erasures. This means that to have an uncorrectable error with minimum distance, the burst should span 5 symbols long when it arrives at the C2 decoder. Since the encoder displaces symbols with 4 blocks after C2 encoding, a burst of 17 blocks would affect 5 symbols but a burst of 16 blocks would only affect 4 symbols. So a burst of 16 blocks can always be corrected by the C2 decoder. Blocks after encoding contain 32 symbols of 8 bits. This means that the maximum duration of a burst can be 16 blocks x 32 symbols/block x 8 bits/symbol, which is 4096 bits. 1 Frame/block contains 6 stereo samples and because the audio sample rate is 44100 samples/s this means the frame rate is 7350 frames/s. This means the maximum duration a burst can occur is 16 frames / 7350 frames/s, which is 0.00218 seconds. Because the scanning velocity of the laser is 1.3 m/s, this means the maximum width of a scratch is 1.3m/s * 0.00218 s, which is 0.00283 meter or 2.83 millimeter. While 4096 bits is the theoretical maximum burst duration that can be corrected, the simulation isn't guaranteed to have erros for a burst slightly longer than 4096 bits. In the simulation, undetectable errors started to occur for scratch lengths a few hundred bits longer than the theoretical allowed maximum. 
\subsection{Linear Interpolation}
% Q4: Describe why interpolation of max 8 subsequent samples works. Relation with sample frequency.
The interpolator works because in the real world sound-waves are also smooth. A soundwave can't jump from one position to another. If you use linear interpolation to draw a line between the safe samples, this will also result in a smooth curve which is a lot better than abruptly stopping the wave.

Because the sample frequency is 44.1 kHz the error of 8 samples only has a duration of 8 samples / 44100 samples/s, which is 0.00018 seconds or 0.18 milliseconds. Since audible audio frequencies only go up to about 20 kHz, the physical sound wave is limited in how fast it can oscillate. This means the time of 0.18 milliseconds is way too short for a physical sound wave to change a lot, so the linear line will be a good approximation. (Ken C. p19, p65-67)

\subsubsection{Random Bit Errors}

The findings of Figure~\ref{fig:bit_error} are discussed in this section. 

\textbf{Configuration 1 (Full CIRC):} \\
In this configuration, we observe a big difference in the ($P(\text{erasure}) = 0.6602$) and the probability of an interpolation failure ($P(\text{interpolation failed}) = 0.0914$ at $p=0.00569$) for the same bit error probability. This performance is directly attributable to the data interleaving process. The $C_1$ decoder can correct up to 2 symbol errors per codeword; if it fails, the uncorrected errors are dispersed before reaching the $C_2$ decoder. Consequently, for a final block to fail, multiple separate $C_1$ blocks must fail simultaneously. When decoding does ultimately fail, the interleaving ensures that the resulting uncorrectable symbols (erasures) are spread out across the time domain. This dispersion allows the audio interpolator to easily reconstruct missing samples across small, isolated data gaps.

\textbf{Configuration 2 (No Interleaving):} \\
Without interleaving, the error correction capability is severely bottlenecked. If the $C_1$ decoder is overwhelmed by a burst error and fails, the $C_2$ decoder will inevitably fail as well, effectively limiting the system to the strength of the first decoder alone. Furthermore, because the data is not dispersed, uncorrectable errors remain grouped together in the time domain. These large, contiguous gaps of missing data cannot be successfully concealed by the audio interpolator, leading to a high rate of interpolation failure.

\textbf{Configuration 3:} \\
This configuration exhibits the highest error correction capacity for uncorrelated errors, capable of simultaneously correcting up to 4 symbol errors per block. The data clearly shows that this code is mathematically the most robust against purely random noise. Similar to Configuration 2, however, there is only a marginal difference between the erasure probability and the interpolation failure probability, indicating that when the decoder does fail, the audio cannot be easily salvaged through interpolation.

\textbf{Conclusion:} \\
Overall, while Configuration 3 performs the best under random noise conditions, it is largely impractical for physical optical media like CDs, which are predominantly susceptible to burst errors caused by scratches or dust. Configuration 2 consistently performs the worst across all metrics due to its lack of interleaving. For low bit-error probabilities, the interleaving between the $C_1$ and $C_2$ decoders of configuration 1 allows it to vastly outperform Configuration 2. Most importantly, Configuration 1 boasts the lowest interpolation failure rate relative to its erasure probability.

\subsection{EFM Modulation}
% Q6: What is EFM and why is it used? Could the EFM demodulator help error correction?
EFM stands for eight-to-fourteen modulation and translates blocks of 8 databits into blocks of 14 bits using a ROM dictionary. The 14-bit patterns are chosen to control the number of transitions between 0 and 1 so a greater data density can be achieved. Since 256 different code patterns are chosen out of the 16384 possible combinations, code patterns will now differ by more than one bit from other code patterns, whereas for the 8-bit patterns flipping one bit would always result in a different code pattern. EFM thus provides a kind of error detection. The 14-bit combinations that are chosen have more than 2 but less than 10 0s appear continuously, which ensures bits can be read correctly on the CD. The blocks of 14 bits are linked with 3 merging bits.

As said the 14-bit patterns have 16384 possible combinations but only 256 of them are valid codewords. If the EFM demodulator receives one of the illegal patterns it can signal to the CIRC an error has occurred and because the CIRC now knows the location of the error it will have to spend less time correcting the error. (Ken C. p79-80)
